# Pokédex

[![CI](https://img.shields.io/github/actions/workflow/status/paulosabra/pokedex/ci.yaml?style=for-the-badge&logo=githubactions&logoColor=white&label=CI)](https://github.com/paulosabra/pokedex/actions/workflows/ci.yaml) [![](https://img.shields.io/badge/Flutter-0553B1?style=for-the-badge&logo=flutter&logoColor=white)](https://flutter.dev/) [![](https://img.shields.io/badge/Claude_Code-DA7756?style=for-the-badge&logo=anthropic&logoColor=white)](https://www.anthropic.com/)

Pokédex is a simple and beautiful way to explore the world of Pokémon. It brings every creature together in one place, so anyone can look up a Pokémon and instantly discover what makes it unique — wherever they are, whether on a phone, in a browser, or on a computer.

![Pokédex project mockup](assets/presentation/project-mockup.png)

## Purpose

The goal of Pokédex is to be the friendliest and most reliable place to discover and learn about Pokémon. Whether you are a lifelong fan, a curious newcomer, or someone who just wants the right detail at the right moment, Pokédex turns a huge universe of information into something easy and enjoyable to explore.

You can browse the full collection at a glance, search by name or number, narrow things down by type or generation, and open any Pokémon to dive into its story — from its description and characteristics to its strengths and how it evolves.

Above all, Pokédex is designed to feel fast, clear, and welcoming, making it effortless for everyone to find and enjoy the Pokémon they care about.

## Architecture

A single-package, **feature-first** Flutter app with a layered structure
(`data` → `domain` → `presentation`). Presentation builds on the `domain`
abstractions; the one deliberate exception is `presentation/coordinators/`,
which read the `pokemonRepository` provider declared in the data layer to drive
background catalogue backfill.

```
lib/
├── main.dart                 # entrypoint → bootstrap(() => PokedexApp())
├── bootstrap.dart            # guarded zone, crash hooks, Firebase + sink init
├── firebase_options.dart     # generated by `flutterfire configure` (web)
├── app/                      # PokedexApp widget + GoRouter (app_router.dart)
├── core/
│   ├── database/             # Drift (SQLite) — local catalogue + DAO
│   ├── network/              # Dio + Retrofit client for PokeAPI
│   ├── error/                # sealed Failure → TE-code mapping
│   ├── observability/        # AnalyticsService / ErrorReporter seam (ADR 0002)
│   ├── ui/ · utils/          # shared widgets and helpers
│   └── pokemon/              # cross-cutting Pokémon utilities
└── features/pokemon/
    ├── data/                 # DTOs, repository, Drift + Dio sources
    ├── domain/               # entities + repository interfaces
    └── presentation/         # Riverpod view-models + screens/widgets
        └── coordinators/     # background backfill (reads the data-layer provider)
```

- **State management:** Riverpod 3 generators (`@riverpod` notifiers) + Freezed
  immutable state.
- **Local-first data:** Drift caches the catalogue; the app reads from SQLite and
  backfills from PokeAPI (Dio/Retrofit). On the web, Drift runs SQLite in a Web
  Worker (see [Web build & WASM assets](#web-build--wasm-assets)).
- **Observability:** a split analytics/error-reporting seam, dark by default and
  enabled per environment via `--dart-define` (see [Observability](#observability)
  and [ADR 0002](docs/adr/0002-split-observability-interfaces.md)).

## Getting Started

### Toolchain

| Tool       | Version                | Notes                                                            |
| ---------- | ---------------------- | ---------------------------------------------------------------- |
| Flutter    | **`3.44.0`** (stable)  | **Pinned.** CI and deploy both pin this exact version.           |
| Dart SDK   | `^3.12.0`              | Bundled with Flutter 3.44.0.                                     |
| Platforms  | Android, iOS, Web, macOS | Web is the deploy target.                                      |

> **Why the pin?** Golden baselines are rendered by a specific engine/Skia +
> bundled font, so an unpinned `stable` can shift sub-pixel anti-aliasing and
> break pixel tests on an SDK bump. The same pin drives CI, the coverage gate,
> and the deployed artifact, so they always agree
> ([ADR 0001](docs/adr/0001-github-actions-builds-vercel-hosts.md)). Use a Flutter
> version manager (e.g. `fvm`) to match `3.44.0` locally.

### Clone, build, run

```bash
# 1. Clone and enter the project
git clone https://github.com/paulosabra/pokedex.git
cd pokedex

# 2. Fetch dependencies (CI and deploy pin the graph with --enforce-lockfile)
flutter pub get

# 3. Generate code (freezed / json_serializable / riverpod / retrofit / drift)
dart run build_runner build

# 4. Run on a device (android, ios, chrome, macos)
flutter run -d <device>
```

> Generated files (`*.g.dart`, `*.freezed.dart`, …) are **git-ignored** and must
> be regenerated after a fresh clone or a model change. The codegen generators
> (`drift_dev`, `freezed`, `riverpod_generator`, `retrofit_generator`) are pinned
> **exact** in `pubspec.yaml` to hold the toolchain on the `analyzer 9` stable
> line — do not loosen them to a caret; see the in-file notes.

### Quality checks

```bash
dart format .
dart analyze --fatal-infos --fatal-warnings
flutter test --coverage
```

> **Local note:** on some hosts (observed on Flutter 3.44.0) `flutter analyze` can crash the
> analysis server. Use `dart analyze` locally; CI runs `flutter analyze` on Linux, which is the
> source of truth for analyzer results.

### End-to-end tests

E2E flows (search → detail, pagination, deep-link errors) run on headless Chrome
against an in-memory Drift database and mocked PokeAPI — deterministic, no
network:

```bash
# ChromeDriver must already be listening on :4444 (CI starts it the same way).
chromedriver --port=4444 &

flutter drive \
  --driver=test_driver/integration_test.dart \
  --target=integration_test/app_test.dart \
  -d web-server --browser-name chrome --headless
```

### Continuous integration

`ci.yaml` gates every PR/push to `epic/**`, `develop`, `main`:
**format → analyze → test → enforced coverage floor → E2E**. The coverage gate
strips generated code from `lcov.info` and fails below **80%** (hand-written
baseline measured at **94.8%**). E2E runs in a separate job so it never writes
into the gated coverage file.

## Observability

The app has two independent seams (see
[ADR 0002](docs/adr/0002-split-observability-interfaces.md)):
`AnalyticsService` (9 anonymized PRD §12 events) and `ErrorReporter` (crash +
handled-failure capture). Both are **dark by default** — `flutter test` and a
plain `flutter run` emit nothing to a vendor (analytics goes to the console in
debug). Vendors are switched on entirely through `--dart-define` flags; no code
change is needed to enable one.

### Environment flags (`--dart-define`)

Single source of truth across local dev, CI build, and runtime. An empty/missing
key keeps the corresponding adapter **dark** (and logs a one-line notice — no
silent no-op).

| Flag                | Type   | Default                    | Effect                                              |
| ------------------- | ------ | -------------------------- | --------------------------------------------------- |
| `ANALYTICS_ENABLED` | bool   | `false`                    | Master analytics switch (turns Firebase on).        |
| `SENTRY_DSN`        | string | `''` (dark)                | Enables Sentry crash reporting when non-empty.      |
| `POSTHOG_KEY`       | string | `''` (dark)                | Enables PostHog when non-empty (native; web deferred). |
| `POSTHOG_HOST`      | string | `https://us.i.posthog.com` | PostHog ingestion endpoint.                         |
| `ENVIRONMENT`       | string | `development`              | Tags events/errors (`preview` / `production`).      |

Read at runtime via `bool.fromEnvironment` / `String.fromEnvironment` in
`lib/core/observability/observability_providers.dart`. `ANALYTICS_ENABLED`
**cannot** vary by build mode from a `fromEnvironment` default — "on in
production" is achieved by the deploy workflow passing the flag, not by a
build-mode-aware default.

### Active sinks by context

| Context                       | Active sinks                                              |
| ----------------------------- | -------------------------------------------------------- |
| `flutter test`                | **NoopSink only** (no console spam, no network)          |
| debug run (no flags)          | ConsoleSink                                              |
| debug run + `ANALYTICS_ENABLED=true` + Firebase | ConsoleSink + Firebase                 |
| production (`main`)           | Firebase (+ Sentry/PostHog if keyed); **no Console**     |
| PR preview                    | dark/console — **never production analytics**            |

### Enable Sentry / PostHog locally and verify

Sentry ships dark until `SENTRY_DSN` is non-empty. To exercise it locally:

```bash
# 1. Run with a real DSN (analytics on so the reporter wires up):
flutter run -d chrome \
  --dart-define=ANALYTICS_ENABLED=true \
  --dart-define=SENTRY_DSN=https://<key>@<org>.ingest.sentry.io/<project> \
  --dart-define=ENVIRONMENT=development

# 2. Verify: trigger an error (e.g. open /pokemon/abc, or hot-restart with a
#    thrown exception) and confirm the event appears in the Sentry project's
#    Issues stream tagged environment=development.
```

PostHog (when keyed) is **native-only for the MVP** — the adapter no-ops on web
(a static `web/index.html` snippet would fire on every preview regardless of
flags, breaking preview isolation). To verify on a mobile/desktop target:

```bash
flutter run -d macos \
  --dart-define=ANALYTICS_ENABLED=true \
  --dart-define=POSTHOG_KEY=phc_<key> \
  --dart-define=POSTHOG_HOST=https://us.i.posthog.com
# Navigate the app, then confirm events land in the PostHog project's Activity feed.
```

> A dark vendor logs `… dark (empty <KEY>)` via `dart:developer`, so you can tell
> from the console whether a vendor is actually live. **Previews never emit to a
> production analytics/crash project** — keep preview keys empty or pointed at a
> separate project.

## Deployment

GitHub Actions builds the web artifact with the pinned Flutter `3.44.0`; Vercel
**hosts the prebuilt output** and applies SPA rewrites + the cross-origin
headers — Vercel runs no build of its own
([ADR 0001](docs/adr/0001-github-actions-builds-vercel-hosts.md)).

```
push / PR ─▶ GitHub Actions (Flutter 3.44.0 + codegen)
          ─▶ flutter build web --release --dart-define=… (inline, from secrets)
          ─▶ vercel build (--prod on main)
          ─▶ vercel deploy --prebuilt
                ├─ pull_request ─▶ Preview URL (analytics-dark)
                └─ push to main ─▶ Production
```

- **Production** publishes **only** on a push to `main`; **previews** on every
  PR. An `epic/**` or `develop` push never promotes to production.
- The build is reproducible: `flutter pub get --enforce-lockfile` + a **pinned**
  Vercel CLI (`vercel@54.6.1`, never `@latest`).
- Deploy is **atomic**: a failed `flutter build` exits non-zero and the job stops
  before `vercel deploy`, so a broken build can never promote.

### First-time setup (one-time)

```bash
# 1. Link the local repo to a Vercel project (creates .vercel/project.json):
vercel link

# 2. Add the GitHub repository secrets (Settings → Secrets and variables → Actions):
#      VERCEL_TOKEN        (from vercel.com/account/tokens)
#      VERCEL_ORG_ID       (from .vercel/project.json)
#      VERCEL_PROJECT_ID   (from .vercel/project.json)
#      SENTRY_DSN          (optional — production crash reporting)
#      POSTHOG_KEY         (optional — production product analytics)
```

> `VERCEL_TOKEN` is passed explicitly via `--token` on **every** `vercel`
> command: the CLI does not read it from the environment for `vercel pull`.

### Preview vs production

| Setting             | PR preview      | `main` production |
| ------------------- | --------------- | ----------------- |
| `ENVIRONMENT`       | `preview`       | `production`      |
| `ANALYTICS_ENABLED` | `false` (dark)  | `true`            |
| `SENTRY_DSN`        | empty (dark)    | prod DSN (secret) |
| `POSTHOG_KEY`       | empty (dark)    | prod key (secret) |

### Rollback

Vercel keeps every deployment immutable, so rolling back is re-promoting a known
good one:

```bash
# Roll back production to the immediately previous deployment:
vercel rollback --token=$VERCEL_TOKEN

# Or promote a specific prior deployment by URL:
vercel promote <deployment-url> --token=$VERCEL_TOKEN

# Inspect recent deployments to pick a target:
vercel ls --token=$VERCEL_TOKEN
```

A bad `main` can also be reverted in git; the next push to `main` rebuilds and
redeploys from the corrected commit.

### Web build & WASM assets

Drift runs SQLite in the browser via two assets vendored in `web/`:

| Asset             | Pairs with                | Current        |
| ----------------- | ------------------------- | -------------- |
| `sqlite3.wasm`    | the `sqlite3` Dart package | matches `2.9.4` |
| `drift_worker.js` | the `drift` package        | matches `2.31.0` |

> **Version-match requirement:** these two files are **not** generated by
> `build_runner` — they are downloaded binaries that must match the resolved
> `drift` / `sqlite3` versions in `pubspec.lock`. When you bump `drift` or
> `sqlite3`, **re-vendor both**: download `sqlite3.wasm` from the matching
> [`sqlite3` package release](https://pub.dev/packages/sqlite3) and
> `drift_worker.js` from the matching [`drift` release](https://drift.simonbinder.eu/web/),
> then commit them. A version mismatch surfaces as a runtime "incompatible
> worker" / load failure, not a compile error.

> **Cross-origin isolation:** the web app serves `Cross-Origin-Opener-Policy:
> same-origin` + `Cross-Origin-Embedder-Policy: require-corp`
> (`vercel.json`) so the browser exposes `SharedArrayBuffer` for Drift's fast
> backend. This can block cross-origin artwork; if images break on a preview,
> fall back to `credentialless`
> ([ADR 0003](docs/adr/0003-coop-coep-and-image-cross-origin.md)). These headers
> are only emitted by the host, so verify on the Vercel **preview**, not local
> dev.
