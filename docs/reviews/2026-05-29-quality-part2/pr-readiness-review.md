## 6. Code Quality Notes

### Strong points

1. **Seam design (D-6):** `AnalyticsService` and `ErrorReporter` are cleanly separated by concern (product analytics vs. crash reporting), matching the plan's architectural decision.

2. **Type safety:** `AnalyticsEvent` is a sealed class, not an enum or string-based event name. This forces compile-time completeness when adding new events (required in T-30b).

3. **Error capture comprehensiveness:** `bootstrap()` wires three error sources (zone-guarded async + FlutterError + PlatformDispatcher). The sync fallback reporter before any async operation ensures C-2 (uncaught during init).

4. **Test thoroughness:** 
   - Events tested for RNF-09 whitelist compliance (no PII)
   - All 9 event constructors exercised in `analytics_event_test.dart`
   - Truth table verified for sink selection under different configs
   - Error handlers tested in `bootstrap_test.dart` with spy reporter

5. **Clear dark-path logging:** When Sentry DSN or PostHog key is missing, a dev log line ("Sentry dark", "PostHog dark") indicates why a vendor is inactive—no silent failures.

6. **Firebase consent anonymization:** D-3 compliance is explicit in `bootstrap()` lines 40–45; all ad-related signals are explicitly set to `false`.

### Areas of note (non-blocking)

1. **Placeholder `firebase_options.dart`:** This file is necessary for the seam to compile but non-functional until replaced by `flutterfire configure` (T-31). The header comment (lines 1–12) and `coverage:ignore-file` annotation are clear. The placeholder values are safe (non-functional PLACEHOLDER_* strings, not actual keys). This is the intended state per the plan.

2. **SDK glue coverage exclusions:** The adapters (`firebase_analytics_adapter`, `posthog_adapter`, `sentry_error_reporter`) have line-level `coverage:ignore-start/end` blocks around the SDK calls. This is justified (untestable vendor SDK glue) and explicitly allowed by §6a.6 (no directory exclusion). Per plan §O-3, this is acceptable.

3. **No PostHog on web (§6a.5):** The `posthog_adapter.dart` no-ops on web (line 23 in `logEvent`). This is noted in the code comment and matches the plan's MVP scope (PostHog web SDK can't read `--dart-define`, so it's deferred).
